    What we'd tell the next team

    Lessons learnt

    Spend day one on paper

    A clear spec and issue-sized tasks are what let the agent build most of the app in a day. Vague issues produce questions or guesses.

    Tests first find what the spec missed

    Writing the permission tests before the code found that a signed-in user could wipe a table. The spec never mentioned it.

    Check reality, not the checklist

    A ticked task had never been built. Production, the git status and the test count are the truth; a list is a claim.

    "Free" has to mean "allowed"

    Read the free-tier terms before choosing. Vercel's is non-commercial only, which ruled it out for a work tool.

    Local success isn't hosted success

    Calendar sync worked locally and had five gaps on production. Budget time for the hosted setup; it's mostly human work.

    Short sessions, written handoffs

    Context is re-read every turn. A fresh session with a 30-line handoff beat one long session on both cost and focus.

    Known gaps

    What the numbers leave out

    Claude chat sessions

    Chat shows no token counts, so a handful of sessions can't be measured: the feasibility review, the design direction, two demo drafts and this wrap-up. Likely a small share next to 57 Claude Code sessions, but that's an estimate.

    GitHub Action runs

    The AI review ran 80 times (54 completed, 25 replaced by a newer push) and @claude built a few issues. They run on the subscription, so nothing extra was paid, but their tokens aren't counted.

    Time outside sessions

    Setting up accounts and dashboards, and reading, isn't logged. The 28 hours is session time only.
